# 第21节 · B2B 经销商业务中心（Dealer Center）系统架构与业务规范

> **文档状态**：已正式确立系统框架与交互蓝图  
> **制定时间**：2026-11-27  
> **核心定位**：ALSVID 官方与全球 B2B 签约经销商的高效率业务经营中台，覆盖订货、交付、车辆档案、财务账期、门店管理及线下试骑服务全链路。

---

## 一、 顶层架构与界面框架

### 1. 核心定位
* **非 C 端商城翻版**：不采用消费级卡片导购，全站采用企业级高密度、高响应效率的业务控制台交互。
* **业务闭环**：以经销商的**采购、履约、门店销售、车辆唯一 VIN 交付、售后索赔与财务账期**为核心。
* **物理隔离与多租户**：不同经销商企业数据在数据库层完全逻辑隔离，当前不做员工角色与多级赋权。

### 2. 界面布局流
* **顶部导航（Header）**：
  * ALSVID® Dealer Center 品牌中英文标示
  * 当前登录企业名称、门店信息与经销商账号
  * 【返回官方网站】、【安全退出登录】快捷入口
* **左侧菜单（Sidebar，固定业务组件，支持按权限动态配置）**：
  * **业务总览**：K01 业务概览
  * **采购与交付**：K02 整车订货、K03 配件订货、K04 采购订单、K05 物流与交付
  * **门店经营**：K06 车辆管理（VIN）、K10 门店管理、K11 客户预约、K08 售后服务
  * **财务与营销**：K07 财务中心、K14 经销商权益、K09 营销素材
  * **企业管理**：K12 消息中心、K13 企业账户（员工与分级权限取消）
* **主工作区（Workspace）**：
  * 欢迎面板与 6 大待办实时看板（待确认订单 / 待交付车辆 / 待付款金额 / 待处理预约 / 待处理售后 / 可用返利）
  * 核心业务单据快捷流转区（快捷批量订货卡片、最新采购订单履约跟踪、品牌官方通知政策）

## 三、 核心业务流转规范

### 1. K02 整车矩阵订货交互
* **SKU 聚合矩阵**：在统一表格内展开车型、颜色、规格、仓库、现货库存、协议批发单价、起订步长（`− 0 +`）；
* **实时试算**：前端即时计算整车总台数、未税货款、增值税（VAT 19% 德国 / 适用税率）、预计交期；
* **单据状态机**：`草稿 (Draft)` → `已提交待审核 (Submitted)` → `已确认锁库 (Confirmed)` → `待付款/账期确认 (PaymentPending)` → `配货发运中 (Fulfilling)` → `已完成 (Completed)`。

### 2. K06 车辆管理与 VIN 唯一生命周期
* **全生命周期唯一追溯**：车辆 VIN 必须严格使用 ALSVID 官方制造主档编码，严禁外部系统重新编号；
* **状态机流转**：
  $$\text{出厂已质检} \xrightarrow{\text{K05 交付}} \text{经销商门店在库} \xrightarrow{\text{K06 销售登记}} \text{已售待绑定} \xrightarrow{\text{车主APP/官网申请}} \text{在役质保期}$$

### 3. K10—K11 官网引流闭环
```
消费者官网 D02 查询门店 → 发起试骑预约 → 对应经销商收到 K11 预约通知
    ↓
经销商确认试骑样车与时间 → 客户到店体验并登记 → 达成购车销售登记 (触发 K06 车辆划扣与 K14 业绩累计)
```

## 四、 系统开发与集成原则

1. **零冗余装修**：B2B 经销商中心属于固定功能型管理后台，**不通过官网装修编辑器逐页装修**，采用标准工程级组件开发。
2. **底层数据 100% 共享**：
   * 车型与 SKU 读取自现有 `products` / `skus` 主档；
   * 库存读取自现有多仓统一库存总账；
   * 售后与零件读取自统一服务工单体系。
3. **安全与权限边界**：
   * 仅经审核通过的签约经销商（`status = 'approved'`）方可发放账户登录 K00；
   * API 强制校验 `dealer_uuid` 上下文，彻底杜绝越权访问。
